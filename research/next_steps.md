# 下一步研究方向：把分数从 0.696 再往上推

现状：主队 public LB **0.696**（两次复现），公开可抄的天花板也是 0.696；榜首 0.774，前 1% 约 0.705，≥0.72 有 46 队。也就是说要「大幅」提分，必须离开公开栈的增量范围（公开栈的改动都在 0.012 的单次提交噪声内）。

## 1. 误差结构：钱在哪

用本项目 26,484 更新五折 OOF（2,699 行 / 150 prompt / 18 类）做的分层分解：

| 指标 | 数值 |
|---|---:|
| 家族准确率（claude/gemini/glm/gpt/qwen/kimi 六族） | 0.8748 |
| 精确准确率（18 类） | 0.6917 |
| 族内条件准确率（族对的前提下再分对类） | 0.7908 |

也就是说：**12.5% 的样本连家族都判错，21% 是族内分错**。metric 是 balanced accuracy，18 类等权，所以：

- 单类召回每提高 0.30，总分 **+1.67pp**；
- 把最差 5 类（当前均值约 0.42）拉到中位（约 0.65），总分 **+6.4pp**。

逐族与逐类现状（`P+.35C+.22G` 视图）：

| 族 | 样本 | 族准确率 | 精确率 | 主要族内混淆 |
|---|---:|---:|---:|---|
| glm | 300 | 0.633 | 0.387 | `glm-5.3` ↔ `glm-5.3-flash`（49 / 25 次） |
| kimi | 150 | 0.513 | 0.513 | 跨族错误为主 |
| gpt | 750 | 0.949 | 0.724 | `5.6-terra`/`5.6-sol`/`5.6-luna` 三者互串 |
| gemini | 600 | 0.988 | 0.733 | `3.7-flash` ↔ `3.8-flash`（43 / 44 次） |
| claude | 749 | 0.891 | 0.760 | 5 个型号互相吸 |
| qwen | 150 | 0.813 | 0.813 | 跨族为主 |

结论：**headroom 集中在三处**——glm 对、gemini flash 对、gpt-5.6 三兄弟；另有 kimi 的跨族塌陷。

## 2. 已验证无效，不要再投入

| 方向 | 证据 |
|---|---|
| 换/加 LoRA 成员 | 我们自己的受控替换 0.684→**0.681**（ref 58396783）；公开侧 17 组 A/B 全部 ≤0.004 |
| GSQ-27B 加份额 | 3%→0.684、6%→0.682、12%→0.681（同码） |
| 按 prompt 簇做 Hungarian/分组分配 | 多次 −0.009 ~ −0.017 |
| 先验/类别偏置校正（面向 balanced accuracy） | 本地实测：OOF 近似均衡，alpha∈[0,1.25] 的 BA 完全不变（0.6917） |
| 内层 24 prompt 选权 | 重选率 31–52%，选出的权重在 outer 上不稳 |

先验校正这一条是本次实测否掉的：OOF 每类样本量接近，`p/prior^α` 对 argmax 不产生任何变化。

## 3. 值得做的方向（按期望增益 / 成本排序）

### 方向 A：族内成对判别器 + 条件重排（最高优先级）

思路：不动现有 13-term 栈，只在「栈的 top-2 预测属于同一族」的行上启用一个**族内二分类器**（glm 对 / gemini-3.7 vs 3.8 / gpt-5.6 三选一），由它决定最终标签。

为什么可能有效：
- 族内错误占全部错误的 21%，且高度集中在 2–3 对；
- 外部池有 238,353 行、覆盖全部 18 类，族内配对样本充足；
- 公开侧的 GLM 似然正是「只改族内那一对」就拿 0.682→0.689，说明**条件式、窄范围的重排**比全局加成员有效得多。

预期：若把 glm 对从 0.387 提到 0.65、gemini flash 对与 gpt-5.6 三兄弟各提 0.15，OOF BA 约 **+2.5 ~ 3.5pp**；映射到 LB 取决于与栈的相关性，保守估计 **+0.005 ~ 0.012**。

成本：判别器可用现成 embedding（Qwen3-Embedding 8B）+ 逻辑回归/小 MLP，CPU 或单卡几小时；先做 OOF 离线验证，不耗提交额度。

### 方向 B：生成式似然扩展到其余开放权重族

已证：GLM-5.3 / Flash 的真实似然重排让 glm 召回 0.27→0.63，LB +0.007~0.012。
限制：只能对**开放权重**的类做。当前 18 类里明确可做的是 glm 两兄弟（已做）与 `qwen3.8-max`（27B 权重与 GSQ 资产已在公开数据集里）；`kimi-k3` 是否有开放权重需要先确认。gemini/claude/gpt 闭源，无法计算似然。

预期：再覆盖 1–2 个开放权重族，**+0.003 ~ 0.008**。天花板低于方向 A，但机制已被证明。

### 方向 C：kimi 的跨族塌陷

kimi 只有 0.513，且错误主要是跨族（被判成别的族），不是族内。这更像**训练数据不足或文本来源分布偏移**，而不是决策边界问题。
做法：先做数据侧诊断（kimi 在外部池的样本量、长度分布、来源），再决定是补数据还是加一个 kimi-vs-rest 的二分类头。
预期：单类 0.51→0.75 就是 **+1.3pp**，是性价比最高的一类，但需要先搞清原因。

### 方向 D：把 Q8 读出改造成 native 槽的形状

`native` 占 40% 份额，是公开栈里唯一「加一个专家跳一档」（0.666→0.680）的位置。我们已验证 Q8 放进 `q8v5`（约 5% 有效份额）是 −0.003，说明**问题在槽位而不是权重质量**。
做法：按 native 的接口重训（Qwen3-Embedding-8B、36 层、深度 (3,6,9,12,18,24,30,36)、最后一 token 池化、5 折、plain+centred 双头）。
预期：不确定，但如果新专家比现专家强 1pp，40% 份额能放大成 **+0.004**；要「大幅」需要新专家本身显著更强。
成本：最高（5 折 × 36 层 embedding 模型），建议在 A/B 有结论后再投入。

### 方向 E：多 seed / 多折平均降方差（便宜）

现有成员多为单次训练；对同一成员训练 2–3 个 seed 取平均，通常能吃到 0.002–0.004 的稳定小增益，且不改变结构。适合与其他方向叠加，单独不构成「大幅」。

## 3.5 A 与 C 的验证协议（2026-11-16 冻结）

方向和判读标准先冻结，避免看到结果后再解释。全部计算在 Kaggle CPU 内核上完成，本机只做元数据读取与代码审阅。

### A 协议

两个互补实验，必须同时报告：

- **A1（可迁移性，主判据）**：族内判别器**只用外部池训练**，应用到官方 OOF 的 2,699 行。
  - 训练前剔除与官方 OOF 文本精确重合（sha1）的样本，并报告剔除数；再报告 200 字符前缀近重复数。
  - 在 `plain_centered_gaussian` 概率上做条件重排：仅当 top-1 与 top-2 同族时触发，`blend_w ∈ {0, 0.25, 0.5, 1.0, 2.0}`，`blend_w=0` 必须精确复现基线 0.69166（自检）。
  - 两组特征独立评测：`char_wb` 3–5 gram TF-IDF；word 1–2 gram TF-IDF + SVD(256)。
  - 报告：pooled BA、ΔBA、逐类召回、逐折 ΔBA、触发率（top-2 同族行数 / 其中 top-1 错的行数）。
- **A2（信号上限，诊断）**：用官方 OOF 逐行文本与真实标签，按 `prompt_id` 分组 5 折训练/评估族内判别器，替换族内决策得到 BA 上界。**明确标注为诊断上界，不可部署**（因为用到了官方 OOF 标签）。
- 判定：A1 的 pooled ΔBA ≥ +2pp 且 ≥4/5 折同向，才值得设计提交侧条件分支；若 A1 接近 0 而 A2 很高，说明外部池与官方分布不可迁移，问题转为「如何为族内判别器造训练数据」，不是放弃方向 A。

### C 协议

先诊断后建模，四个问题按顺序回答：

1. kimi 在外部池与官方集的样本量、长度分布（KS/卡方）、来源组成是否与其他类系统性不同；
2. kimi 文本是否存在异常高的近重复率，以及跨类近重复最近的类是谁；
3. kimi-vs-rest 与 kimi-vs-每族判别器在外部池上的分组 CV AUC，以及迁移到官方 150 行上的召回/精确率；
4. 按 `word_bin` 分层后的条件召回，判断弱是长度效应还是真实风格混淆。

判定：若外部池 AUC 高但官方迁移召回低 → 分布偏移，方向转为补数据；若 AUC 本身低 → 问题在特征/标签，需重新定义 kimi 的可分信号，而不是继续调分类器。

## 3.6 2026-11-16 实测结果（A 与 C 已完成）

两个方向都已在 Kaggle CPU 内核上跑完，结论是**否定性的**，并且否定的原因一致：词面特征的表征力不足。

| 方向 | 实验 | 最好结果 | 判定 |
|---|---|---|---|
| A（族内重排） | 外部池训练判别器 → 官方 OOF，char_wb / word_svd 两组特征 × blend 网格 | **+0.33pp**（char_wb, family, w=0.5，131 行改写；逐折 4 正 1 负，最大负折 −0.74pp） | 不成立 |
| A（组级重排） | 跨族硬分组 + `lift` 加性抬升 + 三种触发 + 两种质量模式 | **+0.44pp**（`gpt_quint`, top2, free, lift=0.5；52 行改写） | 不成立 |
| A（对照） | 用官方 OOF 标签交叉拟合后**完全替换**族内决策 | char 0.4639 / word 0.4302，比基线低 23–26pp | 判别器远弱于栈 |
| C（kimi 诊断） | 样本量 / 长度 / 污染 / 域偏移 / 可分性 | 迁移 AUC 0.767 vs 域内 0.776；池内 CV AUC 0.711 | 不是数据问题，是表征问题 |

关键判读：

1. **错误块大小 ≠ 可修正性**。`glm_claude_triple` 有 191 行错误（完美判别器 +7.09pp），但实测最好的是 `gpt_quint`；glm↔fable 恰恰是词面特征最分不开的一对。
2. **判别器比栈更弱**。即使允许用官方标签交叉拟合，把族内决策交给 TF-IDF 逻辑回归也会掉 23–26pp（族内条件准确率 0.79 → 约 0.5）。所以 A1 的正增益不是"新信号"，而是弱混合下的随机扰动。
3. **A 的机制有结构性缺口**：条件重排要求 top-2 同族，`kimi-k3` 与 `qwen3.8-max` 是单标签族，永远不触发——而 kimi 正是最差的类。组级实验补上了这一环（kimi 门控 +0.15pp），仍然微不足道。
4. **C 的正面副产物**：外部池 → 官方集的迁移几乎无损耗（0.767 vs 0.776），说明外池可以当作训练来源；问题不在数据，在"字符/词 n-gram 看不到栈能看到的东西"。

因此：**便宜的 CPU 条件重排不是提分点**（上限 +0.4pp，且这是在 Q8 单成员 OOF 上测的，映射到 13-term 栈还要再打折）。要把 A 做下去必须换表征（Qwen3-Embedding 或栈自身的 24 层特征），那与方向 D（native 槽重训）本质是同一件事，应合并投入，且需要 GPU。

详细记录见 `research/family_rerank.md` 与 `research/kimi_k3_diagnostics.md`。

## 4. 建议的执行顺序

1. **先做 A 的离线验证**：用现有 OOF 概率 + 外部池训练族内判别器，在 5 折 prompt 分组上诚实评估 `条件重排 vs 现状`。这一步不耗 GPU 提交额度，可以直接判断 A 是否有 2pp 以上的空间。
2. 同时做 C 的数据侧诊断（kimi 的样本量与来源），成本极低。
3. A 若成立，再决定是把它做成提交里的一个条件分支，还是蒸馏进成员训练。
4. B 作为并行的机制扩展（只对开放权重族），D 留到最后。

## 5. 判读口径

- 单次提交噪声约 0.012，任何小于 0.005 的 LB 变化都要多次提交才能判读；
- 优先用 OOF（150 prompt、按 prompt 分组）做门控，只有 OOF 上 ≥2pp 且逐折同向的改动才值得上 LB；
- 不要用 inner-dev 24 prompt 做选权（重选率 31–52%），也不要拿 outer OOF 挑 11 个候选的最大值当结论。
