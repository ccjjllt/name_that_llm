# 公开集成方案的消融研究 · 2026-11-05

本项目复现 Omer 的公开集成，Public LB 为 **0.668**，使用 Open Pool v13 的 190,588 行数据。Ezra 的方案与其核心计算相同。研究重点是拆分各项后处理的贡献、改善同题信息利用，并识别新模型能补充的错误类型。[原方案](https://www.kaggle.com/code/omerfarukmerey/0-668-verifier-matched-rows-pool-prompts) · [Ezra 方案](https://www.kaggle.com/code/ezberch/nlm-v72) · [本项目成绩](submissions.md)

| 阶段 | 配方 | 研究问题 |
|---|---|---|
| 主模型 | 五组 LoRA 配置加一个 DeBERTa 分类器。Qwen3-14B、Qwen3-8B、Llama-3.1-8B 使用多层特征与多个 adapter | 各成员的训练范围与留出映射是否支持可信的 OOF 融合 |
| 文本分类与同题特征 | 四种视图的 SVM 使用官方数据、匹配抽样和 Open Pool，决策分乘 12。内容词 TF-IDF 聚类阈值为 0.15，再计算组中心化特征和部分模型的 Gaussian 头 | 聚类误差如何影响同题证据，单例与小组能获得多少收益 |
| 概率融合 | 互补集成占 15%。前两类概率差小于 0.32 时尝试 ATLAS，混合权重为 0.20。随后做强度 0.30 的软边际调整，目标比例向训练先验收缩 0.35 | 概率校准、ATLAS 覆盖率和测试类别比例变化如何共同影响结果 |
| 最后重排 | 标点证据、同厂商 V40A、V34 pairwise verifier。V40A 在家族内重新分配概率，最大强度 0.10。V34 在前两类概率差小于 0.35 时生效 | 各项重排分别救回和损失哪些文本，是否产生重复修正 |

上述设置来自正式提交所用配方。公开示例只有 3 行，完整推理发生在隐藏测试，整套 0.668 的成绩尚不能确定每项后处理的独立收益。[主模型与融合源码](../runs/public_scan_20261105/generated/infer.py) · [互补集成](../runs/public_scan_20261105/generated/comp_stack.py) · [家族重排](../runs/public_scan_20261105/generated/sibling_style.py)

末尾重排区段存在路径变量名错误，可能在基础预测生成后中断，而原配方的模拟评估又跳过了该区段。因此，后处理贡献需要在同一组预测上逐项重放，单靠原模拟分数无法回答这一问题。[缺陷记录](../runs/public_scan_20261105/v6-code/path_probe.json)

本项目用公开 Qwen3-8B LoRA 的 OOF 预测作代理对照，共 2,699 行、150 个 prompt，五折各留出 30 个完整 prompt。数据按作者注明的官方行序和标签顺序关联，采用作者公布的温度 1.5。每折仅在训练部分估计标点统计和拟合重排器。下表衡量这些方法在单模型预测上的作用。[OOF 来源](https://www.kaggle.com/datasets/utkarshkviim/ntl-lora-v3-qwen3-artifacts/versions/1) · [预测对应关系](../runs/public_scan_20261105/fusion_probe/audit.json)

| 在同一组 OOF 上重放 | Balanced Accuracy |
|---|---:|
| LoRA 基础分 | 0.55937 |
| 加标点重排 | 0.55751 |
| 加标点、再加 V40A 家族重排 | 0.56047 |
| 只加 V40A 家族重排 | **0.56381** |

只加 V40A 时，32 条预测改变，16 条由错变对，4 条由对变错，五折增量全部为正。按 prompt 配对重采样 2,000 次，增量的描述性 95% 区间为 **+0.00184 到 +0.00741**。单加标点救回 4 条、损失 9 条。下一步固定主模型与 ATLAS，在主集成的可信 OOF 上比较基础分、只加 V40A、标点加 V40A，判断这一收益能否迁移到集成。[逐折结果与区间](../runs/public_scan_20261105/style-summary.json)

Verifier 按 128 行分块，参考文本来自当前块，但字符余弦、词余弦、长度比和标点相似度使用了错误的全局索引。从第二块起，这四项特征会取第一块正文，造成特征与查询文本错位。[Verifier 源码](../runs/public_scan_20261105/generated/v34_pairwise.py)

五折配对实验共用相同 verifier、参考集和随机种子，仅改变四项特征的索引。留出 prompt 的 A/B 注释全部剔除，保留原配方在无标签查询文本上拟合词表的做法。原索引独立 BA 为 **0.04779**，修正后为 **0.03817**。受影响的 2,059 行里有 1,865 条改变首选标签，修正版救回 72 条、损失 98 条，五折中两折升、三折降。[配对结果](../runs/public_scan_20261105/verifier_ab/metrics_oof.json)

Verifier 在集成中以小权重修正概率。在同一公开 LoRA OOF 上，1,751 行符合前两类概率差小于 0.35 的使用条件。

| 修正权重 | 原索引融合 BA | 修复索引融合 BA |
|---:|---:|---:|
| 0 | 0.55937 | 0.55937 |
| 0.05 | 0.56011 | 0.56011 |
| 0.10 | 0.56048 | 0.55937 |

正确索引下的结果支持保留权重 0 对照，并重新研究训练配对与推理检索的差异。训练参考文本可改为由推理时相同的每类近邻检索器选择，再比较净救回数与各类别的误伤。公开 Sambit 0.667 方案同时改变索引、候选条件和外部数据，其分数无法隔离单项变化的作用。[融合结果](../runs/public_scan_20261105/fusion_probe/metrics.csv) · [Sambit 方案](https://www.kaggle.com/code/sambitpadhan/ntl-four-top2-gate)

同题数据的分组方式也值得单独比较。对冻结 v13 采用相同长度、去重和每题至少 12 类条件，原 prompt_group 得到 **2,560 组、36,618 行**。改用 prompt_canon，并限于 own_bank、own_text、other_text 三种较强题目证据后，得到 **4,096 组、63,048 行**。先固定共同样本、来源与类别权重，仅更换分组键，再单独增加新组，可以区分分组质量和新增数据的作用。[同题数据统计](../runs/public_scan_20261105/v6-code/pool_panels.json)

查询文本的聚类阈值控制同题信息的覆盖与误配。在官方五个留出池中，每题抽取 1–6 条、使用三个固定种子，阈值从 0.15 降到 0.10 时，同题配对召回从 **77.94% 升到 91.20%**，精度从 **99.35% 降到 98.52%**。下一步通过中心化头与 Gaussian 头比较分类 BA，细分单例、小组和短文本。小验证池与隐藏测试的词频分布可能不同。[聚类结果](../runs/public_scan_20261105/cluster-summary.csv)

同一 LoRA 代理中，Gemini 3.7/3.8 Flash 相互误判 **84 条**，两款 GLM-5.3 相互误判 **68 条**。低于 60 词的 555 条 BA 为 **0.42691**，至少 160 词的 654 条为 **0.63546**。原配方 24,443 条匹配抽样将弯双引号出现率相对官方文本的逐类平均绝对差，从全池的 3.47 个百分点降到 0.47 个百分点，短文本比例差则只从 2.56 降到 2.14。可固定训练规模和来源，比较全类别的长度匹配，再观察这些高混淆类别的变化。[外部池分布](../runs/public_scan_20261105/pool-summary.json) · [混淆明细](../runs/public_scan_20261105/fusion_probe/directed_confusions.csv)

后续比较使用各权重真实的留出映射，按文本 ID 与标签顺序汇总 OOF。各折重新拟合官方标签参与的筛选与统计，分别评价主集成、ATLAS、V40A 和 verifier。ATLAS 的有限评分预算还应比较覆盖率与每千 token 的净救回数，研究按长度顺序处理和按混淆程度分配预算的差异。所有消融报告整体 BA、各类召回、长度分桶和按 prompt 的配对差值，最终再确认对完整集成的贡献。
